# 平台适配与检查

## 按目标版本核实

默认服务 iOS/iPadOS；用户明确要求其他平台时，单独核实其官方规范，不将 iOS 文件直接当作所有平台资源。
采用新外观、资源结构或导出方式前确认项目支持的系统/Xcode；从项目设置、现有资源和官方资料取值，不写死永久适用的槽位表。

- [Apple App icons](https://developer.apple.com/design/human-interface-guidelines/app-icons)
- [Icon Composer](https://developer.apple.com/icon-composer/)
- [Configuring your app icon](https://developer.apple.com/documentation/xcode/configuring-your-app-icon)

Apple 当前指南包含分层素材、系统遮罩与多种外观；Icon Composer 的渲染模式名称与主屏外观名称并非同一套字段。按实际工具界面核实，不能自造 Contents.json 键或分层文件格式。
旧项目可以继续其支持的资源流程；新流程先检查工具链能力，不自动升级 Xcode 或系统要求。

## 制作与导入的区别

- iOS/iPadOS 原始素材保持方形，由系统应用最终圆角遮罩；不要用人工圆角透明图冒充无掩膜母版。
- 分层时优先使用清晰边缘的矢量前景；需要栅格时保留无损原图。
- 若导入背景图层，按官方要求检查满版与不透明；这不表示前景层也必须不透明。
- 传统平面资源另行检查实际槽位要求，包括尺寸、透明条件和色彩信息。预览脚本不是官方资源验证器。
- 新外观保留主体结构；在实际系统支持的深色、清透、着色等外观里检查。脚本上的深背景不等于深色图标变体。
- 仅输出素材时注明尚未完成导入；不手写未经验证的 Icon Composer 文件冒充可打开的工程。

## 检查顺序

1. 检查文件可解码、尺寸、宽高比和实际透明度；与目标资源规范对照。
2. 生成小尺寸预览，查看轮廓、负空间、细节丢失、重心和边缘杂色。
3. 在不同背景下比较；需要的单色或外观变体必须实际制作并分别查看，不能靠灰度滤镜假装系统着色。
4. 有条件时在 Icon Composer 检查系统效果，或集成到 App 后在模拟器/设备主屏查看；记录工具链与系统版本。
5. 修改后复查受影响的尺寸/外观，直到发现的问题解决或明确说明限制。

无图片查看能力时只报告文件检查通过；无可运行项目时不声称主屏显示通过。
不把轮廓看起来不同表述为已经完成竞品查重，不把自身偏好表述为转化率证据。

## 预览脚本

`scripts/preview.py` 接受单帧方形 PNG/JPEG/WebP，生成 24/40/60/120/180 px 的实际像素预览，分别合成在浅、灰、深背景上，并以 JSON 输出源尺寸、透明度与是否存在放大。
输出为平面 PNG。源文件不修改；已存在的输出拒绝覆盖，重新检查时指定新的文件名。
源文件若很小，预览可能放大：报告会注明，不因此声称获得高分辨率母版。
脚本不验证 ICC 配置、Apple 官方遮罩、外观变体、材质或商店合规；也不生成矢量、分层资源或正式 Asset Catalog。

## 交付证据

按任务提供：采用方向和取舍、项目内源文件与导出路径、实际文件规格、已查看的预览、是否导入及运行结果。
明确仍缺的源文件或系统外观，不把所有检查压成一个“通过”。仅用户要求时才创建独立报告。
