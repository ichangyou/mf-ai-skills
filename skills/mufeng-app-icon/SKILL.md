# App icon

目标是做出在主屏上可辨认、与产品相关、经得起缩小的应用图标。
流程：读取真实上下文 → 比较方向 → 统一视觉规则 → 制作与适配 → 实际验证。
本 skill 可独立使用，不要求其他 skill、专用画布或固定生图服务。

## 按需读取

相对路径以实际加载的本文件目录为基准，不以当前工作目录为基准。

- 开始概念设计或比较候选：[设计方法](references/design-method.md)。
- 制作、编辑、生成图片或交付源文件：[素材制作](references/production.md)。
- 导出、集成或交付前：[平台适配与检查](references/platform-review.md)。

## 1. 读取上下文

检查目标项目约定、工作区状态、App 功能、目标用户、品牌颜色、现有 icon、相关界面和 Asset Catalog。
确认本次是新图标、重做、定点精修还是仅导出；保留用户指定的品牌与范围。
从项目确认平台、最低系统版本、Xcode 和图标资源入口。未指定且无法推断时，默认先做 iOS/iPadOS 设计并说明假设，不假称完成集成。

没有产品说明时，先找 README 和界面里的真实任务；仍缺少核心用途时简短询问。
缺少非关键偏好时作出有依据的选择继续，不把完整设计问卷交给用户。
用简短 brief 说明产品关联、核心意象、期望气质、既有约束与交付范围；无需额外文件。

## 2. 比较方向

没有选定方向时，用 2–3 个真正不同的核心意象或构图做低成本可视候选，名称保持稳定。
给每个候选说明产品关联、辨识特征、主要风险和推荐理由；只有提示词或文字描述时明确称为概念，不能称已展示的图标。
已有方向或局部修改直接执行，不重新发散；用户要求先选时等待选择，允许自主完成时说明推荐并继续精修。
不为了候选数量反复调用付费生图；候选可用矢量草图或工具支持的合理批次完成。

## 3. 统一规则并精修

确定一个主要识别特征，围绕它统一轮廓、形状关系、负空间、光学重心和色彩。
保持不同外观下的核心结构；装饰、材质和光影不能压过主体。
先检查缩小效果，再细修大图；不以固定留白比例或数学居中替代视觉判断。
不要将“禁用渐变”“必须玻璃质感”之类风格偏好当成通用质量标准。
不借机改产品名称、页面主题或完整品牌系统。

## 4. 制作与适配

按素材制作参考选择真实可用的矢量、绘图或生图能力；使用宿主提供且有文档依据的工具。
编辑已有图片前先查看原图；保留未修改源文件和采用候选，不覆盖用户已有资源。
工具能力不支持分层、矢量或某种分辨率时如实说明；不能把位图换扩展名冒充矢量或把放大图称为新增细节。

每次生成后确认实际文件存在且非空。立即把采用或交付的图片复制到目标项目明确目录并验证副本，再引用或继续生成；不要只保留在会话缓存。
源文件、透明前景层和最终合成图分别命名。交付目标项目内的可编辑源；仅有栅格结果时说明没有矢量或分层源。
按平台参考核实当前系统和工具链要求，再选择传统 Asset Catalog 或分层图标流程；不要自动迁移项目。

## 5. 实际验证

先运行可用的文件和多尺寸检查，再查看实际图片并修正；采用平台适配参考的检查标准。
有已渲染的方形 PNG/JPEG/WebP 时，可运行本 skill 的预览脚本：

```bash
python3 "$SKILL_DIR/scripts/preview.py" path/to/icon.png --output path/to/project/icon-review/preview.png
```

`SKILL_DIR` 是你根据实际加载路径设置的 shell 变量，不是宿主自动宏；Python 使用环境中已安装 Pillow 的解释器。
脚本只制作 24/40/60/120/180 px、三种背景的平面预览并报告基本文件信息，不生成系统外观、不模拟官方遮罩，也不评分审美。
输入 SVG/PDF 时，先用实际可用的渲染工具导出 PNG；无法渲染时明确未完成预览。

需要集成时，使用项目已有构建命令并在模拟器或设备查看主屏图标；能构建不代表已看过图标。
只有设计任务则不强制集成 App。没有 Xcode、图片查看或生图能力时，分别报告缺口和已完成成果。

## 交付

提供采用方向及理由、项目内文件路径、源文件类型、实际检查和未验证项。
说明哪些是候选、平面预览、可导入资源或已验证集成，不把这些状态混为一谈。
不自动发布、上传商店、做未请求的转化率实验或声称通过商标/商店审核。
Git 行为遵守用户和目标项目约定；两端共用流程，工具缺失时如实降级。
