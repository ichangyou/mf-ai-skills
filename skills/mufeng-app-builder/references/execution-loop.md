# Build 模式：执行循环与失败处理

原则：允许失败，限制重试，保留现场，安全恢复，不伪造成功。

## 开始前

1. `check_plan.py` 输出 PASSED。
2. 工作区干净或已确认；记录起始 commit 作为基线。
3. 基线构建能跑通。跑不通时先修基线，不开始功能任务。
4. 读 `tasks/PROGRESS.md`，确认上次停在哪里。

## 单个任务的循环

```text
选任务：status=PENDING，且 dependencies 全部 SUCCESS；多个可选时取 P0 优先、拓扑序靠前
  ↓
RUNNING：读相关文档和代码，做最小完整修改，补相关测试
  ↓
VERIFYING：运行该任务 verification 中的命令/操作
  ↓
通过 → SUCCESS：证据写入 PROGRESS.md；用户授权自动提交时单独 git commit，否则记录建议提交点
失败 → 进入失败处理
```

一次只做一个任务。不顺手重写无关代码。

## 失败处理

### 1. 先留证据，再改代码
记录：失败命令、退出码、关键日志（脱敏）、当前任务 ID、本次 diff 摘要。

### 2. 分类决定预算

| 类型 | 示例 | 额外重试 | 处理 |
|---|---|---|---|
| 编译错误 | 类型不匹配 | 2 | 每次提出新的根因假设 |
| 测试失败 | 断言失败 | 2 | 检查实现、测试、需求三者哪个错 |
| Lint | 规则不通过 | 1 | 小范围修复 |
| 依赖下载 / 网络 | SPM、npm 超时 | 3 | 指数退避 2s→4s→8s，上限 30s |
| 外部服务 | 429 / 503 | 3 | 优先遵守 Retry-After，限制总等待 |
| 回归 | 修复导致旧测试失败 | 1 | 回到上一个检查点再分析 |
| 架构问题 | 模块循环依赖 | 1 | 先更新 ARCHITECTURE.md 和任务，再实现 |
| 环境缺失 | 没有 Xcode / Docker | 0 | 立即记录阻塞 |
| 需求冲突 | PRD 自相矛盾 | 0 | 阻塞，等用户决定 |
| 安全 / 权限 | 需要生产密钥、付费服务 | 0 | 停止该操作，等人工 |

默认单任务恢复时间不超过 15 分钟。这是起始值，大迁移、外部服务故障需要另定。

### 3. 每次重试必须有新信息
用失败指纹判断是否同一问题：`类别:模块:核心错误`（去掉行号、时间戳、临时路径）。
同一指纹再次出现时，必须写出被否定的旧假设、新证据和新假设；给不出新证据就不再重试，转为阻塞。

### 4. 阻塞记录
写 `tasks/blockers/BLOCK-<NNN>.md`：

```markdown
# BLOCK-001: <标题>
- 任务：T014
- 类别：<上表类型>
- 证据：<命令、退出码、关键日志>
- 已尝试：<每次的假设、动作、结果>
- 根因：<已确认 / 推测>
- 影响：被阻塞的任务 <ID…>；不受影响的任务 <ID…>
- 恢复条件：<需要谁做什么>
- 决定：阻塞该任务，继续独立任务 / 全局停止
```

任务 status 改为 BLOCKED，PROGRESS.md 引用该文件。

## 跳过与停止

- **继续**：被阻塞任务的下游任务也标 BLOCKED；不依赖它、且不会被半成品破坏的任务继续执行。
- **SKIPPED**：只用于 P1/P2，并在 PROGRESS.md 写原因。P0 不能 SKIPPED，也不能从 ACCEPTANCE.md 删除。
- **全局停止（STOPPED）**，满足任一条件：
  - 共享构建或基线测试损坏，且一次回退后仍无法恢复
  - 连续 3 个任务进入 BLOCKED
  - 下一步需要人工确认（密钥、付费、破坏性数据操作、发布、范围变更）
  - 没有可执行任务
  - 所有 P0 SUCCESS 且 MVP Done 检查通过

半成品处理：失败任务的改动不得留在主线上破坏构建。回退到该任务开始前的检查点，或把改动留在单独分支，并在阻塞记录中写明位置。

## 会话恢复

新会话先读 PROGRESS.md、tasks.json、blockers/，检查 `git status` 和最后检查点，再重跑最后一次验证确认现场。
不重放可能产生副作用的操作（扣费、数据迁移、发布、发消息）；这类操作要重新得到确认。
上下文压缩或会话交接前，把当前任务、验证结果、阻塞、下一步写进 PROGRESS.md。

## 结束报告

1. 状态：MVP_DONE / STOPPED（原因）
2. 每个 P0 任务的状态与证据级别（已编写 / 编译通过 / 测试通过 / 实际运行 / 真机）
3. 实际执行的构建和测试命令及结果
4. 阻塞清单与恢复条件
5. 未完成项与风险
6. 建议的下一步

不能把「代码已生成」写成「MVP 完成」。只有 ACCEPTANCE.md 中的 MVP Done 全部满足才算完成。
