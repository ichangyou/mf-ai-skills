# iOS App 起名与查重方法

## 1. 边界

- 输出是**筛查结果和经验判断，不是法律意见**。正式定名前，必须由商标代理人做近似检索并出具意见。
- USPTO 和 TMview 使用的是网页背后的检索接口。它们没有公开文档，结构可能变化。
- TMview 不包含日本的数据。日本需要在 J-PlatPat 手动检索：<https://www.j-platpat.inpit.go.jp/t0100>。
- App Store 搜索接口每次最多返回 200 条结果，只能覆盖所选的几个地区商店。
- 不替用户注册域名，也不替用户提交商标申请或在 App Store Connect 占名。

## 2. 选名标准

1. **目标语言都好读**：逐一检查目标语言（默认 8 种：英、简中、繁中、日、韩、德、法、西）里的读音、片假名或韩文转写，以及有没有不好的含义。
2. **同类不撞名**：同类产品（App Store 的同品类 App、9/42/45 类商标）里没有同名或近似名。
3. **风格符合产品**：例如更短、更有科技感，或者平静克制。
4. **可注册性**：造词或任意词最好。描述性词（例如 lock、key 这类读音）很难注册成商标。
5. **品牌名不承担搜索流量**：App Store 显示名用「品牌名: 品类关键词」的格式，例如「Kypra: Password Manager」。

## 3. 生成候选名

- 一轮生成 20–40 个，混合几种构词方式：
  - 拉丁语或希腊语词根，例如 celare（隐藏）、tacere（沉默）、arca（箱子）、clavis（钥匙）。
  - 两个词根拼成的合成词，例如 key + fold。
  - 改拼写的造词，例如 Kypra。
  - 意象词，例如 Mica（云母）。
- 长度 4–8 个字母，避免连续三个以上辅音。
- 先排除常识范围内的知名品牌，以及和知名品牌只差一个字母的名字（例如 Velkey 对应 Valkey）。注意，这一步是凭知识判断，必须标注为「知识」。
- 普通英文单词（例如 Lanyard、Cairn、Alcove）在 App Store 里往往已经很拥挤，要预期较低的通过率。

## 4. 五步筛查

| 步骤 | 数据源 | 判定 |
|---|---|---|
| ① App Store | iTunes Search API：美区、日区 iPhone，美区 Mac | 有同名品牌（冒号或横线前的部分等于该名）且是安全、金融或工具类 → FAIL；同名但不同类 → REVIEW；名称里含该词的 App ≥3 个 → REVIEW |
| ② USPTO | tmsearch 接口 | 有效商标、属于 9/42/45 类、完全同名或作为独立单词出现 → FAIL；只是字符串包含 → REVIEW |
| ③ TMview | 多国汇总（欧盟、英国、中国、韩国、澳大利亚等） | 同上 |
| ④ 域名 RDAP | `.com`（Verisign）、`.app` 和 `.dev`（Google Registry） | 先用随机域名做自检，必须返回 404；`.app` 组合全部被注册 → REVIEW |
| ⑤ 已注册域名上的网站 | 抓取网页标题和描述 | 有密码、保险库、安全类业务 → FAIL；停放页或空页 → 只记录，不判定 |

通过四步脚本筛查后，还要人工做**网页检索**：搜「名字 + app / software / company」，以及「名字 + password / security」。

## 5. 人工复核规则

| 情况 | 处理 |
|---|---|
| 仅包含匹配，例如 Arcella 命中 MARCELLA，Celare 命中 EXCELARETE | 误杀，改判通过，但要在报告里列出 |
| 图形商标的文字描述里恰好含有该名字（常见于意大利） | 误杀 |
| 商标属于 9 类，但商品是硬件（音箱、显微镜、头盔） | 冲突较弱，但要记录；审查员仍可能认为相关 |
| 商标属于 9 类，商品是「可下载软件」，哪怕领域不同 | 视为实质冲突。审查员通常认为软件和软件相关 |
| 同一持有人在多个地区为同一个名字连续申请 | 视为积极维权的信号，风险上调 |
| 域名在最近 12 个月内才注册 | 说明可能有人正在做同名项目，风险上调 |
| 对方商品描述里有 authentication、identity、security、password（美国商标看 `marks` 的输出，其他地区去对应商标局的官网查） | 直接冲突，FAIL |

## 6. 终选：近似检查与加权评估

1. 对 2–3 个终选名运行 `variants`：自动生成 c/k、y/i、双写或单写辅音等变体，也可以手动补充读音近似的变体。
2. 按下表打分（每项 1–10 分）。权重以密码、安全类产品为例，其他品类可以调整，但要在报告里写明理由。

| 维度 | 权重 | 看什么 |
|---|---|---|
| 商标可注册性 | 30% | 同名和近似商标的数量、类别、地区、持有人的强弱 |
| 主域名控制权 | 20% | `名字.app` 或 `名字.com` 能否注册。安全类产品还要考虑防钓鱼、Passkey 依赖方域名、Associated Domains |
| 与产品调性的契合 | 20% | 和视觉方向、品类信任感是否一致 |
| 多语言读音与拼写 | 15% | 听到读音后能不能拼对；德语的 y 读作 ü、西班牙语的 ll 读作 y、日语和韩语的转写是否稳定 |
| 长度、辨识度、可搜索性 | 15% | 字母数；搜索时是不是全是别的东西 |

## 7. 已知陷阱

- **只做网页检索**：会漏掉 App Store 上大量同名 App（Lanyard 就是这样被漏掉的）。
- **只查 App Store**：会漏掉刚上线、只有官网的同名产品（Keyfold：`keyfold.app` 上线 9 天，正好是同类密码保险库）。
- **用 macOS 的 whois**：可能只查到 IANA 的根记录，返回的创建日期是 1985-01-01 或 2015-06-25，这是顶级域本身的日期，不是具体域名的。改用 RDAP，并先做自检。
- **TMview 结果截断**：常见词会有上万条匹配，只取前几页时，必须在报告里写明「不完整」。
- **把「没找到」写成「不存在」**：只能写「在 X 数据源、Y 范围内没有找到」。

## 8. 报告模板

```markdown
# <产品> 英文名筛查报告（<日期>）

## 结论
- 推荐：<名字>（加权得分 x.x），备选：<名字>
- 决定性因素：<一句话>
- 还需要用户完成：注册域名 / 在 App Store Connect 试占名称 / 用 J-PlatPat 查日本 / 请商标代理人出具意见

## 筛查范围
- 候选 N 个；App Store 地区：…；商标类别：9/42/45；TMview 取回条数及是否截断；日期

## 通过名单
| 名字 | 风格 | App Store | 商标 | 域名 | 网站 | 网页检索 | 风险 |

## 排除名单
| 原因 | 名字（关键证据） |

## 终选对比
<近似检查结果 + 加权评分表 + 依据>

## 未完成与局限
## 来源
```

每条信息都要标注来源类型：「实查」「知识」或「推测」。
