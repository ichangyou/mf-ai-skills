# 检查与交付

## 按使用场景选择检查

先从真实用途决定检查尺度，默认以数字场景为主，不强制做印刷样张。
图形标可以从 16/24/32/64 px 探索小尺寸；横向字标可从 80/120/240 px 宽探索。这些只是检查起点，不是已经验证的最小尺寸。
不同版本维持长宽比，禁止拉伸、裁切或用增加画布留白掩盖问题。

| 检查 | 操作 | 观察 |
|---|---|---|
| 轮廓和负空间 | 在实际像素大小查看图形/组合 | 是否糊成一团、细线消失或孔洞闭合 |
| 字标 | 按目标宽度渲染，核对原名称 | 是否读错、字距失衡、字形替换 |
| 单色 | 实际制作单一油墨/颜色可用的版本 | 结构是否仍成立，不能只做灰度滤镜 |
| 反白 | 将真实反白版本放在深背景 | 形状、孔洞和笔画是否需要光学校正 |
| 透明导出 | 在浅、深底上查看实际 PNG | 是否有白边、假透明或裁切 |
| 源文件复现 | 重开/重渲染 SVG/PDF 或原生源文件 | 字体、图片、路径和依赖是否完整 |
| 目标载体 | 在请求涉及的网页页头、文档等实际位置查看 | 与其他内容的层级和间距是否合适 |

仅创建有用的组合：只做字标不必虚构图形标；仅横向使用不必强制增加竖版。
小尺寸失效时先简化或另做明确标注的小尺寸版，再由观察确定适用范围。

## 从检查到结论

打开源文件查看结构、XML 解析和实际渲染是不同检查。
生成预览后必须查看画面；只读文件名或命令退出码不能证明视觉合格。
同一工具转曲和导出成功不能证明目标软件兼容；需要跨工具交付时，在实际可用的目标渲染器里检查。

没有渲染器时可以检查文件结构并交付，但视觉与字体复现保持未验证。
没有图片查看能力时可以交付实际渲染文件，不能写“已查看并通过”。
没有印刷条件不声称打样通过；没有真实用户研究不声称识别度已获用户验证。

## 最小交付包

按本次请求通常提供：

- 一份实际可编辑源文件；有字标时注明文字源与字体依赖，另存已完成的转曲版本。
- 用途需要的主版本、单色或反白版，以及必要的透明 PNG；标注尚未完成的版本。
- 小尺寸与背景检查图，标明检查的实际尺寸；展示图与正式交付物分开。
- 简短使用说明：版本用途、颜色、字体与素材来源、留白建议、适用尺寸及已知限制。

留白建议可引用设计内一个可说明的单位，但只有实际检查过的范围才称为已验证。
使用说明可放在项目已有品牌文档或一个简短文件里，不默认扩写完整 VI 手册。

## 报告与边界

交代采用方向、主要取舍、文件路径和实际完成的检查。区分概念稿、栅格效果图、矢量源与已经集成的资源。
不能仅凭设计过程声称完成商标检索、法律审查或绝对独创性判断；用户未请求时不追加这一整套流程。
出现相似风险时说明具体观察，继续探索原创形状，不编造已查重的结论。
