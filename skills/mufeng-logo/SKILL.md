# Logo 设计

以真实品牌为依据，制作能够在目标场景使用、修改和复现的标志。
流程：读取上下文 → 比较方向 → 统一图形与字体 → 制作源文件 → 实际验证。
本 skill 独立工作，不依赖其他 skill、固定生图供应商或专用画布。

## 按需读取

从实际加载的本文件目录解析相对路径，不依赖作者电脑路径或宿主专用宏。

- 开始新设计、重做或比较候选：[设计方法](references/design-method.md)。
- 制作图形、字标、矢量与生图概念：[源文件与字体](references/source-and-type.md)。
- 准备交付前：[检查与交付](references/review-and-delivery.md)。

只有 App icon 任务时，优先使用已安装的 `mufeng-app-icon`；本 skill 不把 Logo 自动装进圆角方块。
同时要求 Logo 和 App icon 时，先明确共同的核心图形，再分别适配；其他 skill 不可用时说明边界，不假称已调用。

## 1. 读取真实上下文

检查目标项目说明与工作区状态，读取已有品牌资产、产品介绍、名称和实际使用位置。
没有代码仓库时，从用户提供的品牌材料开始，在用户指定输出目录工作。
确认名称的准确拼写、大小写和语言，以及目标受众、核心价值、主要载体与必须保留的资产。
不擅自改名、加标语或编造品牌历史；仅当缺少名称/用途等信息会改变设计时提问。

用简短 brief 说明品牌关联、期望气质、使用场景、现有约束和交付范围。
能从上下文确认的不要反复询问；非关键偏好可说明假设后推进。

## 2. 比较方向

没有确定方向且需要探索时，制作 2–3 个低成本可视候选，探索不同的图形语言或文字结构。
每个候选用稳定名称说明品牌关联、识别特征、主要取舍，并给出推荐。
只有文字或提示词时称为概念说明，不能称为已展示的 Logo；不要靠漂亮的场景 mockup 代替标志本体。

用户已指定方向或要求定点精修时直接执行，不重新设计整套品牌。
用户要求先选就等待选择；允许自主完成时说明推荐理由并继续，不额外增加审批环节。

## 3. 统一图形与字体

先让标志在简单背景和小尺寸下成立，再调整颜色、材质与精细构造。
选择图形标、字标或组合，以品牌和用途决定；不强制每个品牌都拥有独立符号。
统一轮廓、负空间、笔画关系、光学重心和字距。数学居中或固定比例不能代替实际观看。
文字与图形共享气质，但不靠添加无关装饰来解释品牌。

彩色、单色、反白和需要的组合形式应保留相同身份；仅创建使用场景需要的版本。
沿用真实品牌资产，不描摹其他品牌的可识别标志，不用主观相似性判断冒充正式查重。

## 4. 制作源文件

按源文件参考选择当前宿主真实可用的绘图、生图、排字、转曲和渲染能力。
简单几何可绘制真实矢量；复杂概念可先探索栅格，但最终只声称交付实际完成的源文件类型。
遵守宿主关于生图和图片编辑的规则；编辑已有图像前先查看原图，保留未修改源文件。

字标保留可编辑文字源，并按目标交付需求另存实际转曲的版本；转曲前后都要检查。
没有相应字体或转曲能力时说明限制，不能靠换扩展名或伪造路径声称完成。
每次生成后确认源文件存在且非空，立即将采用/交付图片复制到目标项目明确目录并验证副本，再引用或继续下一张。
所有交付图片与源文件保存在目标项目；临时工具路径不能是唯一副本。

## 5. 实际验证

按检查参考渲染源文件并查看实际结果，覆盖本次需要的小尺寸、单色、反白和目标载体。
文件存在、语法能解析、画面已渲染、视觉已查看是不同状态，分别记录。
修正字形、字距、边缘、裁切、负空间和目标背景上的问题，然后复查。
不把 SVG 内嵌位图称为矢量母版，不把灰度预览称为已设计的单色版本。
缺少渲染或图片查看能力时仍可交付当前成果，但明确哪些检查未完成。

## 交付

说明采用方向与取舍、项目内源文件和导出路径、字体与素材来源、实际检查和未验证项。
按交付参考给出最小使用说明；不自动创建完整 VI 手册、营销物料或全套衍生资产。
不自动发布、上传字体/品牌资产或声称商标可注册。商标调查仅在用户请求时另行处理。
Git 行为遵守目标项目和用户指令。两端共用正文，按各自实际工具能力执行。
